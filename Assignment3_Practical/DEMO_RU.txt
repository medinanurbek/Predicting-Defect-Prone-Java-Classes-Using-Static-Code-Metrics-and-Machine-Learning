КАК ПОКАЗАТЬ РАБОТУ ПРЕПОДАВАТЕЛЮ

1. Дважды нажмите START_DEMO.cmd в этой папке.
   На этом компьютере окружение уже подготовлено.
   На другом компьютере первый запуск установит библиотеки через интернет;
   понадобится Python 3.12. Поэтому заранее проверьте запуск до занятия.

2. Дождитесь строки SUCCESS. New results are in outputs_demo.
   Окно останется открытым, пока вы не нажмёте клавишу.
   На экране будут размеры выборок, результаты обучения и семь проверок PASS.

3. Объясните разбиение:
   Train: Ant, JEdit, POI — 1 679 классов.
   Validation: Ivy — 341 класс. Здесь выбираем модель.
   Test: Camel — 934 класса. Здесь проверяем перенос на другой проект.

4. Покажите outputs_demo/metrics.csv.
   model — алгоритм и набор признаков; split — validation или test.
   all20 — 20 статических метрик, CK6 — шесть метрик CK.
   precision — доля зарегистрированных дефектных среди помеченных;
   recall — доля найденных среди всех зарегистрированных дефектных;
   f1 — совместная оценка precision и recall;
   roc_auc и average_precision — качество ранжирования по риску;
   tn, fp, fn, tp — количества правильных и ошибочных решений.
   Если Excel показывает всё в одном столбце, импортируйте CSV через
   Данные → Из текста/CSV и выберите разделитель «запятая».

5. Покажите outputs_demo/test_predictions.csv.
   Каждая строка — прогноз одной модели для одного Camel-класса.
   actual=1: зарегистрирован хотя бы один дефект; predicted — решение модели.
   probability — оценка модели, не гарантия фактической вероятности дефекта.

6. Покажите outputs_demo/checks.txt и outputs_demo/run.log.
   Это технические доказательства выполнения и проверок.
   PASS означает, что конкретная проверка прошла, а не что модель идеальна.

7. Если спрашивают про код, откройте run_pipeline.py.
   FEATURES — набор метрик, CK — сокращённый набор, SPLITS — разделение.
   build — сборка модели и предобработки.
   measure — расчёт метрик; selection — выбор по validation.
   permutation_importance — первоначальный анализ важности метрик.

8. Покажите в Word раздел Core Practical Component and Initial Implementation.
   Сопоставьте результаты нового запуска с таблицей отчёта.
   Первый полный запуск на фиксированных данных — готов; более широкая
   проверка с поочерёдным исключением проектов остаётся следующим этапом.

КЛЮЧЕВАЯ ФРАЗА
«Мы выбрали XGBoost по validation. На независимом от обучения проекте
Camel он обнаружил 57 из 187 классов с зарегистрированными дефектами,
пропустив 130. Это показывает слабую переносимость, поэтому следующий
шаг — проверка на других проектах. Высокая accuracy сама по себе не
доказывает пользу: Dummy имеет около 80%, пропуская все дефекты».

Файлы в outputs — результаты первоначального эксперимента для отчёта.
Файлы в outputs_demo — результаты последнего демонстрационного запуска.
Они разделены, чтобы сохранить исходное свидетельство выполнения.
